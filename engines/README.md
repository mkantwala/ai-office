# Rust engine sources

AI Office uses Wordcraft for Word documents and Pdfcraft for PDF documents. **Wordcraft is vendored in this repository** at `engines/wordcraft/`: a trimmed workspace (document, layout, render, docx, engine and transitive crates plus the `ai-office-preview` WebAssembly view app) with the Word engine's local changes committed directly in the files. The egui UI, MCP server, desktop/web apps and extra helper crates are not vendored. Only Pdfcraft remains pinned upstream: `sources.json` pins its revision and `pdfcraft.patch` carries the AI Office changes into the ignored `.build/engines/` checkout. Upstream source histories remain in their original repositories.

From the AI Office root, run `node scripts/prepare-office-engines.mts` to fetch the pinned Pdfcraft revision and apply its patch into the ignored `.build/engines/` directory. The build script prefers those prepared sources, then falls back to the sibling checkouts used during development. `WORDCRAFT_SOURCE`, `PDFCRAFT_SOURCE` and `CARGO_TARGET_DIR` remain available as overrides; a `WORDCRAFT_SOURCE` experiment or the ignored `.build/engines/wordcraft` checkout still takes precedence over the vendored tree when present. Reference clones for reading upstream wordcraft code live beside this repository (`../wordcraft` / `../wordcraft-upstream`); copy needed code into `engines/wordcraft/` and commit it.

The setup script verifies patch checksums and refuses to overwrite an existing checkout with a different version. Generated WebAssembly, dependencies, local documents, build output and profiles are not source files and are not committed. The original sibling working trees are preserved.

PDF integration now pins PdfCraft 0.10.1. Its patch adds a small persistent `sangam-pdf` worker around the upstream automation table. The application uses a platform-native executable for complete file workflows, signing, forms and exports; PDF no longer uses the limited WASM preview bridge. Word remains WebAssembly-backed. A future PowerPoint engine — [Deckcraft](https://github.com/storytold/deckcraft), a Wordcraft sibling — will be vendored the same way when PPT agent work starts; see [AI_OFFICE_AGENT_PLAN.md](../AI_OFFICE_AGENT_PLAN.md) for the parity TODOs.

After preparing sources, build PDF with `node extensions/ai-office-pdf/build.mts --native` (also the default PDF build), then Word with `node extensions/ai-office-pdf/build.mts --word`. PDF output is under ignored `media/native/<platform>-<arch>/`; it is built per target platform, stripped of debug symbols and packaged with upstream notices/attribution. A Node extension host is required. The source patch and checksum, rather than generated binaries or a sibling checkout, are the reproducible deliverable.
